## 1. Выбор источника данных и обоснование

Для реализации лабораторной работы выбраны два официальных бесплатных REST API:

1. **NASA NeoWs (Near Earth Object Web Service) REST API** — основной источник варианта:
   - Эндпоинт: `https://api.nasa.gov/neo/rest/v1/feed?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&api_key=DEMO_KEY`.
   - *Обоснование:* Официальный сервис Лаборатории реактивного движения NASA (JPL) и Центра изучения околоземных объектов (CNEOS). Предоставляет актуальные астрономические данные с физическими параметрами (оценочные минимальные и максимальные диаметры, скорости относительно Земли в км/с и км/ч, точные дистанции пролёта в километрах и лунных расстояниях LD, классификацию потенциальной опасности `is_potentially_hazardous_asteroid`).
   - Использование ключа `DEMO_KEY` позволяет запускать проект локально любому проверяющему без регистрации приватных ключей. Серверный модуль `lib/neo.js` проксирует вызовы, предотвращает блокировку браузерной политикой CORS и скрывает сетевые сбои за предсказуемыми кодами состояния.

2. **Frankfurter API (v2) с провайдером `providers=ecb`** — источник конвертера валют:
   - Эндпоинт: `https://api.frankfurter.dev/v2/rates`.
   - *Обоснование:* Свободный JSON-интерфейс к официальным публикациям Европейского центрального банка. Работает без токенов, возвращает точную дату фиксации курса и позволяет запрашивать исторические данные.

1. **Календарная проверка дат и защита от несуществующих дней**:
   - Агент сразу реализовал чистый алгоритм григорианского календаря (високосный год: делимость на 4, исключение столетий кроме кратных 400). Даты вида `2026-02-31` или `2026-04-31` корректно блокируются до отправки запроса с понятным текстом ошибки.

4. **Сквозной набор тестов**:
   - 31 тест из 31 успешно прошел с первого запуска раннера `npm test`.
5. **Двухрежимный интерфейс**:
   - Реализована плавная навигация между трекером астероидов и валютным конвертером в едином стилевом оформлении.

## 4. Ошибки агента, расхождения и исправления вручную

В процессе работы агента Antigravity возникли следующие расхождения и ошибки, потребовавшие вмешательства:

1. **Ошибка отображения пустых дней в API NASA**:
   - *Проблема:* Когда агент первоначально тестировал даты без зарегистрированных сближений (например, `1800-01-01`), NASA API возвращает `{ element_count: 0, near_earth_objects: {} }`. В первоначальной версии парсера агент ожидал, что ключ даты `near_earth_objects[targetDate]` всегда является массивом, что приводило к исключению `TypeError: Cannot read properties of undefined (reading 'map')`.
   - *Исправление:* В функцию `parseNeoResponse` добавлена проверка наличия ключа даты: если массив отсутствует или пуст, возвращается нормализованный снимок с `element_count: 0` и пустым списком астероидов, что позволяет интерфейсу мягко вывести сообщение и предложить сохраненный кэш.

2. **Конфликт заголовков Content Security Policy (CSP)**:
   - *Проблема:* В базовом сервере `server.js` действовал строгий CSP: `style-src 'self'`. При отрисовке динамических элементов и подсветки опасных объектов браузер блокировал стили индикаторов. Также блокировались ссылки на внешнюю фавиконку и JPL-ссылки.
   - *Исправление:* В `server.js` директивы CSP были скорректированы: добавлен `'unsafe-inline'` для динамических стилей карточек и расширен `img-src 'self' data: https:`.

3. **Синхронизация даты и статуса кнопки при смене вкладок**:
   - *Проблема:* При быстром переключении с вкладки NASA на вкладку Валют кнопка конвертации оставалась в предыдущем состоянии блокировки, так как события `input` не вызывались повторно.
   - *Исправление:* В модуль `public/app.js` добавлен явный триггер функции `updateControls()` при переключении табов.

4. **Локализация чисел в русской типографике**:
   - *Проблема:* Агент изначально использовал стандартный `toLocaleString()` без параметров, из-за чего в зависимости от настроек хост-системы Windows разделителем тысяч становилась неразрывная точка или запятая, ломая регулярные выражения тестов.
   - *Исправление:* Была жестко зафиксирована русская локаль `'ru-RU'` в функциях `formatThousands` и `formatMoney`, а разделители проверены регулярными выражениями с учетом юникодных пробелов.
