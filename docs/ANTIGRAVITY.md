# Учебный процесс и передача в Antigravity

Эти документы подготовлены Codex. Они не являются доказательством запуска Spec Kit / Copilot / Antigravity.

## Как выполнить именно требуемый процесс

В отдельной чистой папке, чтобы не смешивать уже существующую реализацию с этапом спецификаций:

```powershell
uv tool install specify-cli
specify init currency-lab --integration copilot
cd currency-lab
```

Нужны Python 3.11+ и uv. В чате Copilot по очереди выполнить актуальные команды (Copilot по умолчанию использует дефис):

```text
/speckit-constitution Принципы: русский доступный GUI, проверка данных, явный кэш, unit-тесты, отдельные ветки, честный отчёт.
/speckit-specify Создай конвертер валют по требованиям приложенного specs/001-currency-converter/spec.md. На этом этапе код не писать.
/speckit-clarify
/speckit-plan Node.js 22+, vanilla HTML/CSS/JS, локальный сервер, Frankfurter v2 с providers=ecb, localStorage, node:test. Используй приложенный plan.md как исходный технический план.
/speckit-tasks
/speckit-analyze
```

Перед реализацией проверить результат и закоммитить спецификации в отдельной ветке. Создать и слить настоящий PR спецификаций. Открыть репозиторий в Antigravity, создать ветку реализации и передать агенту:

> Прочитай конституцию .specify/memory/constitution.md и все файлы specs/001-currency-converter/. Выполни задачи по порядку. Не подменяй реальные данные демонстрационными. Записывай обнаруженные расхождения и исправления для REPORT.md. Запусти npm test, проверь GUI, ошибки сети и восстановление кэша после перезапуска. Покажи итоговый diff.

Зафиксировать фактически выбранную модель в интерфейсе Antigravity и результаты каждой попытки. Тесты — отдельная ветка и PR. Не копировать в отчёт неподтверждённые названия моделей из задания.

## Ветки текущей локальной заготовки

main — исходный каркас; specs/currency-converter — требования; feat/currency-converter — реализация поверх спецификаций; test/currency-converter — тесты и итоговые документы поверх реализации. Ветки зависимые, слияний main здесь нет.

После создания отдельного GitHub-репозитория добавьте его как origin и опубликуйте ветки. PR последовательно: specs → main, затем feat → main, затем test → main. Используйте merge commit, чтобы сохранить общие исходные коммиты зависимых веток; squash/rebase потребует переноса оставшихся изменений. Здесь PR не созданы: адрес удалённого репозитория не предоставлен.
