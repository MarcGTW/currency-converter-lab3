# Спецификация · NASA NEO Tracker (Трекер околоземных астероидов)

- Версия: 1.0.0
- Дата: 18.11.2026
- Статус: Утверждено для реализации в Google Antigravity
- Источник данных: NASA NeoWs (Near Earth Object Web Service) REST API feed

---

## 1. Назначение и контекст

Приложение предназначено для мониторинга и наглядной визуализации околоземных астрономических объектов (Near Earth Objects, NEO), пролетающих вблизи орбиты Земли в выбранную дату. Проект реализует вариант Лабораторной работы №3 по дисциплине «Инженерия подсказок и разработка на основе спецификаций (Spec-Driven Development)».

Инструменты разработки:
- Подготовка спецификаций: формат GitHub Spec Kit (Markdown-артефакты: конституция, спецификация, план, задачи, анализ согласованности).
- Сборка и кодогенерация: агент Google Antigravity (модель Gemini 3.8 Flash).

---

## 2. Пользовательские сценарии (User Stories)

### US1. Просмотр астероидов на выбранную дату
Как пользователь, я хочу указать интересующую дату (ГГГГ-ММ-ДД) и нажать кнопку «Получить данные», чтобы увидеть список всех обнаруженных NASA околоземных астероидов за этот день с подробными характеристиками (диаметр, скорость сближения, расстояние пролёта, флаг опасности).

### US2. Идентификация опасных объектов
Как исследователь или любитель астрономии, я хочу мгновенно выделять потенциально опасные астероиды (`is_potentially_hazardous_asteroid === true`) с помощью контрастного визуального индикатора (бейдж тревоги, светящаяся рамка) и фильтровать список только по опасным объектам.

### US3. Справка об источнике и времени ответа
Как пользователь, я хочу видеть точный источник данных («NASA JPL NeoWs API») и метку времени получения ответа, чтобы быть уверенным в актуальности информации.

### US4. Работа при пустых днях или отсутствии данных
Если на выбранную дату в каталоге NASA нет зарегистрированных пролётов (пустой список) или API возвращает пустой результат, приложение не падает, а автоматически предлагает/подтягивает последний успешно сохранённый день из локального кэша и явно выводит предупреждение пользователю.

### US5. Работа в условиях отсутствия сети (Offline / Fallback)
Если отсутствует интернет-соединение или сервер NASA временно недоступен:
- Приложение не падает с необработанной ошибкой.
- Выводится понятное русскоязычное сообщение об ошибке сети.
- Если в локальном кэше есть ранее сохранённый снимок, приложение предлагает загрузить данные последнего успешного сеанса с указанием точной даты и времени кэша.

### US6. Защита от некорректного ввода
Пользователь не может отправить запрос с некорректной датой (например, «31 февраля», буквы, пустая строка, даты в неверном формате). Кнопка получения данных остаётся заблокированной до ввода корректной даты, а под полем ввода отображается подсказка с ошибкой.

### US7. Долговечный локальный кэш
Успешно полученные данные автоматически сохраняются в постоянном хранилище браузера (`localStorage`), сохраняя структуру снимка, и остаются доступными после перезагрузки страницы или перезапуска приложения.

## 3. Функциональные требования (FR)

- **FR01: Графический веб-интерфейс (GUI)**. Приложение обладает отзывчивым, адаптивным интерфейсом космической тематики (темный фон, контрастная типографика, адаптация под экраны от 360px до 1920px+).
- **FR02: Валидация даты**.
  - Формат строго `ГГГГ-ММ-ДД` (`YYYY-MM-DD`).
  - Календарная корректность: валидация числа дней в месяцах (включая проверку високосных лет для 29 февраля, блокировка 30/31 февраля).
  - Диапазон допустимых дат: от `1900-01-01` до разумной даты будущего (`+1 год` от текущей).
- **FR03: Состояние кнопки запроса**. Кнопка «Получить данные» активна только при валидной дате в поле ввода.
- **FR04: Запрос к источнику данных**.
  - Обращение к официальному NASA NeoWs Feed API (`https://api.nasa.gov/neo/rest/v1/feed?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&api_key=DEMO_KEY`).
  - Серверный прокси `/api/neo?date=YYYY-MM-DD` предотвращает утечки заголовков, соблюдает CSP и нормализует сетевые сбои.
- **FR05: Разбор и трансформация сущностей астероидов**.
  Для каждого астероида в ответе извлекаются и рассчитываются:
  1. `id` и `name` (название объекта).
  2. `estimated_diameter`:
     - Минимальный и максимальный диаметр в метрах (например, `120 – 270 м`).
     - Если диаметр >= 1000 м, отображение в километрах (`1.2 – 2.7 км`).
  3. `relative_velocity`:
     - Скорость относительно Земли в км/с и в км/ч с аккуратным разделителем разрядов.
  4. `miss_distance`:
     - Расстояние сближения в километрах (например, `4 250 180 км`).
     - Расстояние в лунных дистанциях (LD, 1 LD ≈ 384 400 км), например `11.06 LD`.
  5. `is_potentially_hazardous_asteroid`: булев флаг (Опасен / Безопасен).
  6. `close_approach_date_full`: дата и время максимального сближения.
  7. Ссылка на JPL Small-Body Database (`nasa_jpl_url`).
- **FR06: Отображение источника и метки времени**.
  В интерфейсе выводятся: плашка «Источник: NASA NeoWs API» и время формирования ответа (локальное время с секундами).
- **FR07: Обработка пустых дней / выходных каталога**.
  Если на выбранную дату список объектов пуст (`element_count === 0`), приложение информирует пользователя и предлагает переключиться на последний успешно сохранённый день из кэша.
- **FR08: Обработка ошибок сети и сбоев API**.
  При сбое сети (HTTP 5xx, Network Timeout, Offline) интерфейс выводит понятное сообщение и предлагает активировать сохранённый кэш при его наличии.
- **FR09: Локальное кэширование снимка**.
  - Валидация структуры перед сохранением в `localStorage` (ключ `neo_cache_v1`).
  - При повреждении структуры кэша приложение не падает, а мягко игнорирует битые данные.
- **FR10: Интерактивные фильтры и сортировка списка**.
  - Быстрый переключатель: «Все объекты» / «Только потенциально опасные (Hazardous)».
  - Сортировка: по расстоянию сближения (сначала ближайшие), по диаметру (сначала крупные), по скорости.
  - Поиск по имени или номеру астероида.

## 4. Нефункциональные требования

- **NFR01: Производительность**. Рендеринг списка до 50 астероидов занимает менее 100 мс без подвисания браузера.
- **NFR02: Доступность (a11y)**. Поддержка навигации с клавиатуры, семантические теги (`<main>`, `<article>`, `<button>`), `aria-live` для динамических сообщений и статусов.
- **NFR03: Автономность тестов**. Unit-тесты запускаются через стандартный раннер `node --test` без необходимости обращения к внешней сети (с моками сетевых ответов).
- **NFR04: Чистая архитектура**. Бизнес-логика, парсер и валидация даты изолированы от DOM в модуле `neo-core.js`, что позволяет тестировать их напрямую в Node.js.
